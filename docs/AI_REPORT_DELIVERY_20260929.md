# AI 解析交付与退款修复

## 范围

- 仅修改新请求的资料格式、明确拒绝检查及失败后的修改问题入口。
- 保持当前每次 2 积分、模型、生成参数、扣费事务和按钮立即进入生成中的逻辑。
- 不处理历史测试订单，不把已完成报告改为退款。

## 提示词和资料

短提示词独立存放在 `server/prompts/ai_report_cultural_context.md`，说明传统文化学习、娱乐参考及不可编造依据。不规定字数、档位或报告格式，不试图绕过模型安全规则。

服务端将识别到的卦象 JSON 转成标签文本，保留原始问题、起卦时间、本卦、动爻、互卦、变卦和资料分项。健康等问题保持原文，不伪装成其他问题。原有命盘纯文本及未知格式不改写。用户资料和后台快照不删除。

## 交付检查

即时请求和本地 Worker 在保存成功报告前共享检查：空内容、平台结构化拒绝、明确拒绝且没有实质传统解读，进入已有失败退款流程。

不单靠字数判定。短报告、负面结论、免责声明及同时包含实际分析的边界说明不会仅凭这些特征退款。该检查是保守规则，不是完整语义判断，未覆盖的措辞可能漏判；混合或不明确内容保留现有反馈入口，不能承诺百分之百识别。

退款按实际订单扣积分数，通过原有原子 RPC 完成；同订单重复提交不会再次调用 AI 或重复退款。没有自动反复调用模型。仅在数据库确认 refunded 时提示已退款，数据库故障不能假称到账。

## 发布与测试

这项增量不需要新增 SQL。此前结算保护迁移仍按其部署说明执行，本次不替代它。发布后须重启本地 AI Worker，才能使用新的检查代码；旧队列任务继续保留提交时的提示词。

自动测试使用模拟模型响应，不发送真实付费请求。检查命令：

```text
npm run check:api
npm run test:server
flutter test test/features/ai_reports test/widget_test.dart --no-pub
flutter analyze --no-pub
```

人工验收：正常问事与命盘各一次，检查资料、起卦时间与报告内容；遇到拒绝时核对订单 refunded、扣款及退款流水各一条、积分恢复，点击“修改问题”应聚焦输入框，再点击“重新解析”才创建新请求。刷新不能再次退款。不要为了触发拒绝连续发送付费测试。

文化语境提示是否降低真实拒绝率，需要上线后的真实样本验证；测试通过不代表模型保证解读所有问题。
